# 詳細設計書

## 1. モジュール詳細

---

### 1.1 main.c

#### 処理フロー

```
main(argc, argv)
  1. argc < 2 → usage() 表示してエラー終了
  2. cdbg_resolve_program(argv[1]) : カレントディレクトリ優先でパス解決
  3. spawn_argv[] に argv[1..] を格納（最大 256 要素）
  4. cdbg_init(&dbg)
  5. cdbg_set_run_target(&dbg, spawn_argv)
  6. cdbg_run(&dbg, NULL) : プログラムを起動してエントリで停止
  7. cdbg_repl(&dbg) : REPL ループ開始
  8. EXIT_SUCCESS で終了
```

---

### 1.2 process.c

#### cdbg_resolve_program

- 名前に `/` が含まれる → パスとして扱いそのままコピー
- 含まれない → `./<name>` が存在すればそちらを使用
- それ以外 → `PATH` 検索はせずそのまま（`execv` に委ねる）

#### cdbg_process_spawn

```
fork()
  子プロセス:
    1. setpgid(0, 0)       ← debuggee を独立プロセスグループへ
    2. ptrace(PT_TRACE_ME) ← 自身をトレース対象に登録
    3. malloc_stack_logging が true なら setenv("MallocStackLogging", "1")
    4. execv(argv[0], argv)

  親プロセス:
    *child_pid = pid; return 0
```

#### cdbg_process_wait

```c
do {
    ret = waitpid(pid, status, 0);
} while (ret == -1 && errno == EINTR);  // SIGINT による中断を再試行
```

### 1.3 memory.c

#### アクセス経路の優先順位

```
cdbg_mem_read(pid, addr, buf, len)
  1. task_for_pid() で Mach タスクポート取得
  2. 成功 → mach_vm_read() でまとめて読み取り
  3. 失敗 → ptrace(PT_READ_D) で 1 バイトずつ読み取り

cdbg_mem_write(pid, addr, buf, len)
  1. task_for_pid() で Mach タスクポート取得
  2. 成功 → mem_write_mach()
       2a. mach_vm_write() 直接試行
       2b. 失敗（保護あり）→ mach_vm_protect(R|W|COPY) → write → protect(R|X)
  3. 失敗 → ptrace(PT_WRITE_D) で 1 バイトずつ書き込み
```

**理由**: `mach_vm_write` は書き込み保護ページに対して失敗するため、`mach_vm_protect` で一時的に書き込み可能にする。これはブレークポイント（テキストセクション書き換え）に必要。

### 1.4 regs.c

#### レジスタ取得

```
cdbg_regs_get(pid, tid, regs)
  1. task_for_pid() → task
  2. thread_for_task_tid(task, tid) → thread
       tid == CDBG_TID_PRIMARY: task_threads(task) の threads[0]（先頭＝プライマリ）
       それ以外: task_threads(task) を全走査し、thread_info(THREAD_IDENTIFIER_INFO)
                 の thread_id が tid に一致するスレッドを探す
                 （マッチしなかった全ポートは mach_port_deallocate で解放）
  3. thread_get_state(thread, CDBG_THREAD_FLAVOR, &regs->native, &count)
  4. thread_get_state(thread, CDBG_NEON/FP_FLAVOR, &regs->neon/fp, &count)
     （同じ thread ポートを使い、deallocate は両呼び出しの後に行う）
```

`cdbg_regs_set`/`cdbg_regs_set_by_name` も同じ `tid` 引数を取り、`thread_for_task_tid` 経由で対象スレッドの `thread_set_state` を呼ぶ。`dbg->current_tid`（`threads`/`thread` コマンドで選択）がこの `tid` として渡されるため、`regs`/`print`/`show locals|args`/`tb`/`up`/レジスタ代入はすべて選択中のスレッドに対して動作する（詳細は [02_基本設計書.md 15章](02_基本設計書.md) を参照）。フレームアンワインド (`cdbg_regs_frame_up`) はメモリ読み取りのみで完結するため tid を取らない。

#### スレッド一覧取得

```
cdbg_threads_list(pid, out[], max_count, count_out)
  1. task_for_pid() → task
  2. task_threads(task) → 全スレッドポート
  3. 各スレッドについて thread_info(THREAD_IDENTIFIER_INFO) で tid を取得し、
     out[i] = { tid, is_primary: i==0 } に格納（先頭のみ is_primary=true）
  4. 全スレッドポートを mach_port_deallocate
```

`cmd_threads`（`debugger.c`）はこの結果の各スレッドについて `cdbg_regs_get(pid, tid, &regs)` で PC を読み、`lookup_symbol_for_pc`/`cdbg_lineno_line_at_pc` でシンボル化して1行ずつ表示する。行頭2文字は `thread_is_current`（`dbg->current_tid` と一致、または primary かつ `current_tid == CDBG_TID_PRIMARY`）が真なら `*`、`thread_is_locked`（`dbg->thread_lock_active` かつ `dbg->locked_tid` と一致）が真なら `L`（両方成立時は `*L`）。`cmd_thread`（`debugger.c`）は同じ列挙結果の n 番目を `dbg->current_tid` に設定し、`cdbg_refresh_regs` で `dbg->regs` を即座に切り替える。

#### スレッド一時停止/再開（`cdbg_thread_suspend`/`cdbg_thread_resume`）

```
suspend_or_resume_thread(pid, tid, suspend)
  1. task_for_pid() → task
  2. thread_for_task_tid(task, tid) → thread
  3. suspend ? thread_suspend(thread) : thread_resume(thread)
```

`thread_suspend()` はスレッドごとの一時停止カウントを +1 する Mach API で、ptrace の `PT_CONTINUE`/`PT_STEP`（プロセス全体を再開する）とは独立して効く。カウントが 1 以上のスレッドは、タスク全体が再開されても実行されない。

`cmd_lock`（`debugger.c`）は `cdbg_threads_list` で列挙した対象スレッド以外の全スレッドに `cdbg_thread_suspend` を呼び、成功した tid を `dbg->suspended_tids[]` に積む。途中で失敗した場合は、それまでに suspend した分だけ `cdbg_thread_resume` でロールバックしてからエラーを返す（一部のスレッドだけ止まったままになる状態を避けるため）。`cmd_unlock` は `dbg->suspended_tids[]` を逆に辿って `cdbg_thread_resume` を呼び、`thread_lock_active` をクリアする。

#### アーキテクチャ抽象化

| 操作 | ARM64 | x86_64 |
|---|---|---|
| PC 取得 | `regs->native.__pc` | `regs->native.__rip` |
| FP 取得 | `regs->native.__fp` | `regs->native.__rbp` |
| SP 取得 | `regs->native.__sp` | `regs->native.__rsp` |
| トラップバイト | `0xd4` (BRK) | `0xcc` (INT3) |

#### レジスタ一覧

**ARM64**

| 種別 | レジスタ | Mach 構造体フィールド |
|---|---|---|
| 汎用 (GPR) | x0-x28, fp(x29), lr(x30), sp, pc, cpsr | `arm_thread_state64_t.__x[]`, `.__fp`, `.__lr`, etc. |
| NEON/FP | v0-v31 | `arm_neon_state64_t.__v[]` (`__uint128_t`) |
| FP 制御 | fpsr, fpcr | `arm_neon_state64_t.__fpsr`, `.__fpcr` |

**x86_64**

| 種別 | レジスタ | Mach 構造体フィールド |
|---|---|---|
| 汎用 (GPR) | rax-rsp, r8-r15, rip, rflags, cs, fs, gs | `x86_thread_state64_t.__rax` 等 |
| SSE | xmm0-xmm15 | `x86_float_state64_t.__fpu_xmm0`-`.__fpu_xmm15` (`_STRUCT_XMM_REG`) |
| SSE 制御 | mxcsr | `x86_float_state64_t.__fpu_mxcsr` |
| x87 FPU | st0-st7 | `x86_float_state64_t.__fpu_stmm0`-`.__fpu_stmm7` (`_STRUCT_MMST_REG`) |
| x87 制御 | fctrl, fstat, ftag | `x86_float_state64_t.__fpu_fcw`, `.__fpu_fsw`, `.__fpu_ftw` |

#### 新規関数

| 関数 | 説明 |
|---|---|
| `cdbg_regs_get_by_name(regs, name, out)` | レジスタ名で値を取得（整数として返す） |
| `cdbg_regs_set_by_name(pid, tid, regs, name, value, is_float, fvalue)` | レジスタ名で値を設定し thread_set_state で書き戻す |
| `double_to_80bit(d, bytes)` | IEEE 754 double → 80ビット拡張精度（x87 st レジスタ用） |

#### フレームアンワインド (cdbg_regs_frame_up)

```
x86_64:
  1. PC が PUSH RBP (0x55) ならスタックトップの戻りアドレスを使用
  2. FP != 0 → [FP+0]=saved_FP, [FP+8]=ret_addr を読んで移動

ARM64:
  1. LR（リンクレジスタ）が有効なら PC を LR に設定
  2. FP != 0 → [FP+0]=saved_FP, FP を更新
  3. SP を FP+16 に設定
```

### 1.5 breakpoint.c

#### cdbg_bp_enable

```
1. cdbg_mem_read(pid, addr, &saved_byte, 1)
2. bp->addr = addr; bp->saved_byte = saved_byte; bp->enabled = true
3. cdbg_mem_write(pid, addr, &TRAP_BYTE, 1)
```

#### cdbg_bp_matches_pc

```c
// x86_64: INT3 実行後に IP が +1 されるため
#if defined(__x86_64__)
return bp->addr + 1 == pc;
#else
return bp->addr == pc;
#endif
```

#### ブレークポイントヒット後の再開処理（debugger.c 内）

```
0. switch_current_tid_to_breakpoint_hit() : cdbg_threads_list で全スレッドを列挙し、
   各スレッドの PC をブレークポイントアドレス群と照合。一致するスレッドがあれば
   current_tid をそのスレッドに切り替える（macOS の ptrace はプロセス全体に
   作用するため、トラップしたのが current_tid とは限らない）
1. cdbg_bp_disable() : 元のバイトを復元
2. cdbg_regs_set_pc(pc - 1) : PC を bp->addr に戻す（x86_64 のみ）
3. cdbg_regs_set() : PC をデバッギに書き戻す
4. シングルステップで 1 命令実行
5. cdbg_bp_enable() : トラップ命令を再設置
```

#### ブレークポイントの再起動時再設定（cdbg_run 内）

`cdbg_breakpoint_t` は `{addr, saved_byte, enabled}` に加えて、元の `break` コマンド引数をそのまま保持する `spec[128]` を持つ（`cmd_break` が設定時に記録する）。`run` は新しいプロセスを fork/exec するため ASLR スライドが変わり、以前のプロセスに書き込んだトラップ命令はそのままでは無意味になる。そのため `cdbg_run` は：

```
1. 既存の dbg->breakpoints[] から spec[] を一時配列に退避
2. dbg->breakpoints[] をクリア（breakpoint_count = 0）
3. 新プロセスを spawn し、シンボル/行情報・ASLR スライドを更新
4. 退避しておいた spec を 1 つずつ cmd_break() に渡し、新プロセスに対して再解決・再設定する
```

これにより「`run` 前に設定したブレークポイントは再起動後も保持される」という仕様を満たす。

### 1.6 watchpoint.c

ソフトウェアブレークポイント（テキストセクション書き換え）とは異なり、CPU のハードウェアデバッグレジスタを使用する。シングルステップ不要で、書き込みが発生するまでフルスピードで実行できる。

`cdbg_t::watchpoints[]` の配列インデックスがそのままハードウェアスロット番号になる（最大 4 個 = `CDBG_WP_MAX_HW`）。

#### cdbg_wp_hw_install / cdbg_wp_hw_uninstall

デバッグレジスタはスレッドごとの状態であり、`pthread_create()` で生成されたスレッドはゼロクリアされた自分専用のレジスタを持つ。1 スレッドだけに設定すると、そのスレッド以外が監視対象を読み書きしてもトラップが発生しないため、**タスク内の全スレッド**に同じ内容を設定する。

```
共通の流れ（for_each_thread ヘルパーに集約）:
1. task_for_pid → task_threads でタスク内の全スレッドポートを列挙
2. 各スレッドについて:
   a. thread_get_state(..._DEBUG_STATE64, ...) でデバッグレジスタを取得
   b. 該当スロットのフィールドを書き換え（install）／クリア（uninstall）
   c. thread_set_state(..._DEBUG_STATE64, ...) で書き戻す
3. スレッドが 1 つも無ければ、あるいはいずれかのスレッドで失敗すれば -1 を返す
```

`report_stop`（`resync_watchpoints_to_all_threads`）は、停止するたびに現在有効な各ウォッチポイントについてこの `cdbg_wp_hw_install` を再度呼び出し、その時点で存在する全スレッドに設定し直す。これにより、ウォッチポイント設定後に生成された新しいスレッドも、次にデバッガが制御を取り戻した時点で監視対象に含められる（生成から次の停止までの間のアクセスは検出できない）。

**ARM64 (DBGWVRn_EL1 / DBGWCRn_EL1)**

```c
WCR = E(bit0=1) | PAC(bit1-2=0b11: EL0+EL1) | LSC(bit3-4=0b10: store、`/r` 指定時は 0b11: load or store)
    | BAS(bit5-12: バイトオフセットに応じたビットマスク)
WVR = addr & ~0x7  // 8 バイト境界に切り詰め、BAS でオフセットを表現
```

8 バイト境界をまたぐアドレス/サイズの組み合わせは `-1` を返して拒否する（BAS で表現不可）。

**x86_64 (DR0-DR3 / DR7)**

```c
DRn = addr                          // 自然境界にアラインされている必要がある
DR7 の該当スロット:
  local enable bit (bit 2n) = 1
  R/W フィールド (bit 16+4n, 2bit) = 0b01 (write、`/r` 指定時は 0b11: read/write)
  LEN フィールド (bit 18+4n, 2bit) = size に応じて 00/01/11/10 (1/2/4/8 バイト)
```

自然アラインされていないアドレスは `-1` を返して拒否する。

#### watch コマンド (cmd_watch, debugger.c)

構文: `watch [/r] [/1|/2|/4|/8] <expr>`（`/r` と `/1`〜`/8` は順不同、いずれも省略可）。
`parse_watch_flags()` が式本体の前から `/` で始まるフラグを剥がして解釈する。

```
1. state == IDLE → エラー
2. 引数なし → cmd_show_watchpoints にフォールバック（一覧表示）
3. parse_watch_flags() で先頭の /r・/1・/2・/4・/8 を読み取る
   - /r: 書き込みだけでなく読み取りもトラップ対象にする（CDBG_WP_ACCESS）
   - /1,/2,/4,/8: 監視サイズを式の型から推定せず明示指定する
   - 不明なフラグはエラー
4. cdbg_resolve_lvalue_expr_sized で式のアドレスとサイズを解決
5. サイズ決定: 明示指定があればそれを使用、なければ watch_hw_size_for() で
   1/2/4/8 バイトに丸める（8 バイト超は先頭 8 バイトのみ監視）
6. cdbg_wp_hw_install を試み、失敗したらサイズを半分にして再試行（アライメント救済。
   ただし明示指定サイズの場合はリトライしない）
7. 現在値を old_value として保存し、dbg->watchpoints[] に登録
```

#### ウォッチポイントヒット検出 (find_watchpoint_hit / report_watchpoint_hit, debugger.c)

ハードウェアウォッチポイントの停止は命令実行後（値が既に書き換わった後）に発生するため、DR6/ESR のデコードは行わず、単純に「停止するたびに現在値を読み直して前回値と比較する」方式で検出する。

```
find_watchpoint_hit:
  各 enabled な watchpoint について現在値を読み込み、old_value と比較
  変化していれば、その index を返す（old_value はまだ更新しない）
report_watchpoint_hit:
  現在値を再読み込みして Old/New を表示し、old_value を更新してから
  print_stop_location で停止位置を表示する
```

呼び出し箇所: `report_stop`（`continue`/`si` 後）、`cdbg_step_next_line`、`cdbg_next_source_line`（`step`/`next` 中）。いずれもソフトウェアブレークポイントのトラップ判定より後に評価する。

**既知の制約**:
- ローカル変数のスタックアドレスを監視している場合、変数がスコープを抜けた後にそのスタック領域が別の変数に再利用されると、無関係な書き込みとして誤検出されることがある（gdb/lldb のスコープ追跡なしウォッチポイントと同様の制約）
- ウォッチポイント設定後に生成されたスレッドが、次の停止（`report_stop`）より前に監視対象へアクセスした場合は検出できない（スレッド生成イベントを捕捉する仕組みがなく、`resync_watchpoints_to_all_threads` は停止時にしか動けないため）
- `/r`（read/write）指定時、`counter++` のような read-modify-write アクセスは読み出し側でトラップすることがある。ハードウェアウォッチポイントのトラップ自体は正しく発生するが、その時点では値がまだ書き換わっていないため `find_watchpoint_hit` の前後比較では「変化なし」と判定され、"Watchpoint hit" ではなく単なる "Stopped" として報告される

### 1.7 syms.c

#### シンボルロード戦略

```
cdbg_syms_load(executable_path)
  1. Mach-O をメモリマップ → __TEXT vmaddr を link_base として保存
  2. [executable_path, dSYM パス] それぞれに対して:
       syms_load_from_nm() : nm -n <path> の出力をパース
       成功したら return 0
  3. 全失敗 → Mach-O nlist_64 を直接パース (syms_load_macho)
  4. dSYM が存在すればそちらも試みる
```

#### シンボルフィルタリング条件 (sym_name_interesting)

- 名前が空でない
- type が `?` または `-` でない
- 先頭文字が `.` または `L` でない（ローカルラベル除外）
- 先頭文字が印字可能文字

#### シンボル名検索 (cdbg_syms_lookup_name)

```
入力名が '_' で始まらない場合、先頭に '_' を付けて検索
（C の external シンボルは Mach-O で先頭 _ が付く慣習）
```

#### ASLR スライド算出 (cdbg_syms_update_slide)

```
mach_vm_region_recurse で VM マップを先頭から走査:
  実行可能(EXECUTE|READ) な最初のリージョン先頭 = 実行時 __TEXT 先頭
  slide = 実行時先頭 - link_base
```

### 1.8 lineno.c

#### DWARF 行情報ロード

`dwarfdump --debug-line <executable>` の出力をパースして `cdbg_line_entry_t[]` を構築する（`lineno_load_from_dwarfdump`）。失敗時は `__debug_line` セクションを自前でパースする経路にフォールバックする（`parse_line_table`、DWARF4/5 対応）。

dwarfdump の `--debug-line` 出力は、コンパイルユニットごとに次の3ブロックからなる:

```
debug_line[0x...]                              # ここでコンパイルユニットが切り替わる
include_directories[  N] = "path"               # ディレクトリテーブル（インデックス N）
file_names[  N]:                                # ファイルテーブル（インデックス N）
           name: "foo.c"
      dir_index: 0
           ...
Address            Line   Column File   ISA ...  # 実データ行。File 列はファイルテーブルの
0x0000000100000510     19      0      0   0 ...  # インデックス（上記の N）を指す
```

`lineno_load_from_dwarfdump` は `include_directories[]`/`file_names[]` をそれぞれ動的配列（`str_table_t`/`file_table_t`、コンパイルユニットが切り替わるたびにリセット）に格納し、各データ行の **File 列の値をそのままファイルテーブルの添字として**使ってパスを解決する（`dwarfdump_resolve_path`）。

**過去の不具合**: 旧実装は File 列を一切読まず、直前に出現した `name: "..."` 行（＝ファイルテーブルの最後のエントリ）を無条件に全データ行へ適用していた。1つの CU が複数ファイル（例: `pthread_create` を呼ぶソースでは `_pthread_t.h` 等のヘッダも file_names に載る）を参照する場合、実際にはほぼ全ての行が主ソースファイル（file_names[0]）を指しているにもかかわらず、ファイルテーブル末尾のヘッダファイル名で上書きされて表示されていた（`lines`/`show`/停止位置表示などが誤ったファイル名を報告する、または `lines <ファイル名>` のフィルタが一致せず空になる、という形で症状が出る）。File 列を正しく参照するよう修正済み。

```
cdbg_line_entry_t {
    uintptr_t address;   // リンク時アドレス
    uint32_t  line;
    uint32_t  column;
    char      file[512];
}
```

行情報のスライドは `cdbg_lineno_update_slide` で `cdbg_syms_t` と同様に算出。

#### 主要ルックアップ

| 関数 | 用途 |
|---|---|
| `cdbg_lineno_lookup_pc` | runtime_pc → line_entry |
| `cdbg_lineno_lookup_line` | file + 行番号 → line_entry |

| `cdbg_lineno_lookup_next_line_after_pc` | ステップオーバー終端検出 |

#### 一覧表示（`lines` / `lists`）

### 1.9 コマンド解析・式評価（cmd_lexer.l / cmd_grammar.y / ast.c / ast_eval.c / ast_expr.l / ast_expr.y / expr.c）

REPL の行解析と `print`/`set`/`watch` の式解析は、どちらも flex（字句解析）+ bison（構文解析）で実装する。文法（構文）はパーサジェネレータに、DWARF 参照などの意味解析は引き続き `debugger.c` の関数に担当させ、両者を分離する。詳細なアーキテクチャ説明は [02_基本設計書.md 14章](02_基本設計書.md) を参照。

#### cmd_lexer.l / cmd_grammar.y（コマンド解析）

```
cdbg_repl_dispatch_line(dbg, line):
  1. cmdyy_reset_state()          // start condition を INITIAL に強制リセット
                                   // （直前の行が構文エラーで ARGSTATE/WORDSTATE の
                                   //   まま終わっている可能性があるため）
  2. cmdyy_scan_string(line)
  3. cmdyyparse(dbg, &outcome)    // %parse-param 経由で dbg・結果を受け渡し
  4. cmdyy_delete_buffer(...)
  5. cmdyy_reset_state()
  6. return outcome               // CDBG_REPL_OK / CDBG_REPL_QUIT / CDBG_REPL_FATAL
```

字句解析器の start condition:

| 状態 | 用途 | 該当コマンド |
|---|---|---|
| `INITIAL` | コマンドキーワードの認識 | 全コマンド |
| `ARGSTATE` | 残り全体を 1 個の `RESTLINE` として捕捉 | `help` `run` `print`/`p` `set` `show` `del` `watch` `unwatch` `dis` `list` |
| `WORDSTATE` | 空白区切りで `WORD` を複数返す | `break` `x` `lines` `lists` `syms` `thread` `lock` |

`continue`/`step`/`si`/`next`/`regs`/`kill`/`quit` は REPL ループの制御フロー（プロセス未起動チェック、致命的エラー時の中断）を持つため、`cdbg_repl_cmd_continue` 等 `cdbg_repl_outcome_t` を返す専用関数（`debugger.c`、`repl_cmds.h` で宣言）を経由する。それ以外のコマンドは対応する `cmd_*` 関数（同じく `debugger.c`）をそのまま呼び出す。

引数の過不足（例: `break` に引数なし、`x` に3個以上の引数）は文法規則の分岐で個別に扱うか、bison の構文エラーとして拒否する。

#### ast.h / ast.c（AST 定義）

```c
cdbg_ast_t {
    cdbg_ast_kind_t kind;  // NUM/FLOAT/IDENT/BINOP/POS/NEG/NOT/BNOT/ADDR/DEREF/MEMBER/ARROW/INDEX
    cdbg_ast_op_t   op;    // kind == BINOP のとき有効
    uint64_t        num;   // kind == NUM
    double          fnum;  // kind == FLOAT
    char           *name;  // IDENT/MEMBER/ARROW の識別子名
    cdbg_ast_t     *lhs;   // 左辺 / 単項演算のオペランド
    cdbg_ast_t     *rhs;   // 右辺 / INDEX の添字式
}
```

#### ast_expr.l / ast_expr.y（式の字句解析・構文解析）

演算子優先順位は `%left`/`%right`/`%prec` 宣言（低優先度から高優先度の順）:

```
%left OROR
%left ANDAND
%left '|'
%left '^'
%left '&'
%left EQ NE
%left '<' '>' LE GE
%left LSHIFT RSHIFT
%left '+' '-'
%left '*' '/' '%'
%right UNARY_PREC        /* 単項 + - ! ~ & * */
%left '.' ARROW '['      /* 後置演算子（最優先）*/
```

`.`/`->`/`[]` は `expr` に対する左再帰規則（`expr '.' IDENT` 等）として定義されており、`a.b.c` や `p->q->r`、`arr[i+1]`（添字が定数に限らず任意の式）のような多段アクセスを自然にサポートする。

#### ast_eval.c（AST 評価器・左辺値リゾルバ）

```c
cdbg_ast_t *cdbg_ast_parse(const char *text);
int cdbg_ast_eval(cdbg_t *dbg, cdbg_ast_t *node, cdbg_expr_result_t *out);
int cdbg_ast_resolve_lvalue(cdbg_t *dbg, cdbg_ast_t *node, uintptr_t *addr_out,
                            cdbg_var_info_t *var_out);
bool cdbg_ast_is_lvalue_shaped(const cdbg_ast_t *node);
```

- `cdbg_ast_eval`: リテラル評価、算術・比較・論理演算、変数読み取り、`*expr`（ポインタ参照読み取り）、`&lvalue`（アドレス取得）を実装。`IDENT`/`MEMBER`/`ARROW`/`INDEX` の評価は内部で `cdbg_ast_resolve_lvalue` を呼びアドレス解決してから読み取る。
- `cdbg_ast_resolve_lvalue`: ノード種別ごとにアドレス + `cdbg_var_info_t`（型・サイズ・符号・配列/ポインタ情報）を解決する。`debugger.c` の意味解析関数（`resolve_variable_address`・`lookup_struct_member`・`pointer_pointee_type`・`type_element_size`・`type_is_scalar`）を `varinfo.h` 経由で呼び出す。`MEMBER`/`ARROW` は再帰的に `lhs` を解決してから `lookup_struct_member` を呼び、`INDEX` は `lhs` が配列か（アドレス+要素サイズ）ポインタか（値を読んでから要素サイズ）で分岐する。
- `print`/`set`/`watch` はいずれもこの 2 関数を共有する。`cdbg_ast_resolve_lvalue` が失敗するノード種別（`IDENT`/`MEMBER`/`ARROW`/`INDEX`/`DEREF`）は、`cdbg_ast_eval` に回しても内部で同じ解決を試みて同じ理由で失敗するだけなので、呼び出し側（`cmd_print` 等）はフォールバックしない（二重エラーメッセージの防止）。

#### expr.c（互換ラッパ）

`cdbg_expr_eval`（`debugger.h` 公開 API）のみを実装。`cdbg_ast_parse` → `cdbg_ast_eval` に委譲する薄い関数で、DWARF 参照・字句解析・構文解析のロジックは一切持たない。

#### 浮動小数点数リテラル


### 1.10 debugger.c

#### REPL ループ

```c
for (;;) {
    fputs("cdbg> ", stdout); fflush(stdout);
    if (fgets(line, sizeof(line), stdin) == NULL) {
        if (ferror(stdin) && errno == EINTR) {
            clearerr(stdin); putchar('\n'); continue;  // Ctrl+C
```

#### ステップ制御

**step (ソース行ステップイン)**

```
cdbg_step_next_line:
  current_line = lineno_lookup(pc)
  ループ:
    cdbg_single_step → cdbg_wait
    new_line = lineno_lookup(new_pc)
    new_line != current_line → 停止
    ブレークポイントにヒット → 停止
    ウォッチポイントにヒット → 停止
```

**next (ソース行ステップオーバー)**

```
cdbg_next_source_line:
  ループ:
    call_return_address(pc) で直接 call 命令(x86_64: 0xe8 / arm64: BL)を検出
      検出できた → step_over_call(): 戻り先に一時ブレークポイントを設置 → continue → 到達したら削除
      検出できない（間接/PLT 呼び出し等） → cdbg_single_step によるシングルステップ 1 回分
    ブレークポイント/ウォッチポイントにヒット → 停止
    行番号が変わった → 停止
```

`call_return_address` は直接 call のオペコードしか認識しないため、動的リンクされた関数への間接呼び出し（PLT 経由の呼び出しなど）は検出できず、呼び出し先全体を 1 命令ずつシングルステップすることになる。ループの上限は `CDBG_MAX_STEP_ITERATIONS`（100000）で、これに達すると "Step limit exceeded" として打ち切る。この経路は実時間で数秒かかることがある。

**マルチスレッドプログラムでのスレッド一時停止**

`PT_STEP`（`cdbg_single_step` が使う）はカレントスレッドに 1 命令分のトラップを仕掛けるだけで、他スレッドを一緒に止める仕組みを持たない。上記のシングルステップフォールバックのように内部で `PT_STEP`+`waitpid` を何度も繰り返す場合、その間ずっと他スレッドが実時間で動き続けてしまう（マルチスレッドデバッグ機能追加当初の既知の問題だった）。

これを防ぐため、`cdbg_step_next_line`/`cdbg_next_source_line`（`step`/`next` の本体）はループに入る前に `step_thread_guard_begin()` でカレントスレッド以外の全スレッドを `cdbg_thread_suspend()`（`lock` と同じ、ptrace とは独立した Mach の `thread_suspend()`）で一時停止し、ループを抜けたら（成否・プロセス終了に関わらず、`goto done;` で単一の出口に集約して）必ず `step_thread_guard_end()` で `cdbg_thread_resume()` して戻す。`cdbg_repl_cmd_si` は 1 命令分のステップしか行わないため、同じガードを begin/end だけの形（ループ内の追いつき処理なし）で自前に持つ。`lock` で既に他スレッドを長期的に一時停止中（`dbg->thread_lock_active`）の場合は、二重に一時停止カウントを操作しないようこの処理をスキップする。

**ステップ途中で生成されたスレッドを取りこぼすレース（`step_thread_guard_catch_up`）**

ループ開始前に 1 回だけ全スレッドを一時停止するだけでは不十分な場合がある。`pthread_create()` のように、ステップの**実行中**に新しいスレッドが生成されるケースでは、そのスレッドはループ開始時点ではまだ存在せず一時停止の対象から漏れる。放置すると、新スレッドが自分自身のブレークポイント（0xCC/BRK）に実際に到達してしまうことがあり、これは「メインスレッドの `PT_STEP` 完了を待つ `waitpid()` に対して、別スレッドが無関係な SIGTRAP を起こす」状況を生む。検証の結果、この状況では `waitpid()`（`cdbg_wait` → `cdbg_process_wait` → `__wait4`）が完全にブロックしたまま二度と返らない（`sample` でスタックトレースを採取して確認、macOS の ptrace 実装の制約と見られる）ことを確認した。`b worker` → `b main` → `run` → `c`（main で停止）→ `n`（`pthread_create` をまたぐ）を 10 回前後繰り返すと、体感で 1 回程度の頻度でこの無限ハングが再現した。

対策として、`cdbg_step_next_line`/`cdbg_next_source_line` はループの**各反復の先頭**で `step_thread_guard_catch_up()` を呼び、その時点で存在するがまだ一時停止リストに無いスレッドを検出して即座に `thread_suspend()` する。1 反復＝1 命令（または 1 回の `step_over_call`）分のステップ幅しかないため、新スレッドが生成されてから自分のブレークポイントに到達できるだけの猶予（スレッド起動処理は通常それよりずっと長くかかる）よりも十分短く、実用上このレースを塞げる。

**`current_tid` が非プライマリスレッドのときに一時停止対象を誤ってプライマリスレッドまで含めてしまう不具合（修正済み）**

上記の対策を最初に実装した際、`step_thread_guard_catch_up()` は「`current_tid` 以外の全スレッド」を一時停止対象にしていた。ところが検証の結果、`ptrace(PT_STEP, dbg->pid, ...)`/`ptrace(PT_CONTINUE, dbg->pid, ...)` は `dbg->current_tid` を一切参照せず、常に**プロセスのプライマリスレッド**のコンテキストに対して単一命令トラップを仕掛けることが判明した（`cdbg_regs_get`/`cdbg_regs_set` が Mach API で任意のスレッドを明示的に指定できるのとは対照的）。

具体的には、`break worker` → `run` → `c`（ワーカースレッドのブレークポイントにヒットし `current_tid` がワーカーに切り替わる）→ `si` を実行すると、"current_tid 以外" の一時停止ロジックはプライマリスレッドを（current_tid ではないという理由で）一時停止してしまう。しかし `PT_STEP` が実際に単一ステップさせるのはそのプライマリスレッド自身なので、一時停止によってプライマリスレッドが凍結された結果、`PT_STEP` が待っている単一命令トラップが永久に発生せず、`waitpid()`（`cdbg_wait` → `cdbg_process_wait` → `__wait4`）がブロックしたまま返らなくなっていた（`sample` でスタックトレースを採取し、`cdbg_next_source_line`/`debugger.c` の該当行で `__wait4` に入ったまま止まっていることを確認）。一時停止を無効化して同じ状況で `si` を実行すると、ハングはしないが `pc` が `libsystem_kernel.dylib` 内のシステムコール境界（ワーカースレッドではなくプライマリスレッドがブロックしている場所）に着地することも確認し、「`current_tid` に関わらず常にプライマリスレッドが単一ステップされる」という前提を裏付けた。

修正（第 1 段）: `step_thread_guard_catch_up()` の一時停止対象からプライマリスレッド（`threads[i].is_primary`）を常に除外する。これによりハングの頻度は大きく下がったが、根絶はできなかった。

**それでも残った断続的なハング**: `current_tid` を非プライマリのままにして `n` を連続実行するテストを繰り返したところ、数回に 1 回の頻度で再び `cdbg_next_source_line` → `cdbg_wait` → `__wait4` でブロックするケースを `sample` で確認した。`PT_STEP` がどのスレッドを実際にステップ対象とするかはカーネル側が「現在トレース中」として保持しているスレッドの状態に依存すると見られ、一時停止の有無だけでは確実に防げない非決定的な問題であることが分かった。

修正（第 2 段、最終）: 一時停止まわりの調整だけでは安全性を保証できないため、`current_tid != CDBG_TID_PRIMARY` のときは `step`/`si`/`next` の実行そのものを `require_primary_thread_for_step()` で拒否するように変更した。"Cannot single-step: ... Run 'thread 0' ..." というエラーを表示し、`thread 0` でプライマリスレッドに戻ってから再実行するよう促す。`continue`・ブレークポイント・ウォッチポイントはタスク全体に対する再開／トラップであり `current_tid` に依存しないため、この制約を受けず、非プライマリスレッドの状態確認（`regs`/`print`/`tb` 等）自体は引き続き問題なく行える。

任意のスレッドを個別に単一ステップさせるには、ptrace ではなく Mach の `thread_set_state` でハードウェアの単一ステップフラグ（x86_64: EFLAGS の TF ビット、arm64: `MDSCR_EL1` の `SS` ビット等）を対象スレッドに直接設定し、その結果を例外ポート経由でハンドリングする設計が必要になる。BSD ptrace ベースの現行アーキテクチャでは対応できないため、現状は前述の拒否＋案内に留めている。

#### print フォーマット指定 (`print_format_t`, `parse_print_format`)

`print`/`p` は `print/x`・`p/x` のように、コマンド名直後の `/` に続く 1 文字でGDB互換の出力形式を指定できる（字句解析は `cmd_lexer.l` がコマンド名部分を丸ごと `p/x` のような文字列として拾い、`cmd_print_from_repl` が `/x 式` の形に組み立て直してから `cmd_print` に渡す。実際の解釈は `cmd_print` 内の `parse_print_format()` が行う）。

| 文字 | 意味 |
|---|---|
| `x` | 16進数 |
| `d` | 符号付き10進数（整数のデフォルト） |
| `u` | 符号なし10進数 |
| `o` | 8進数 |
| `t` | 2進数 |
| `a` | アドレス表示。`lookup_symbol_for_pc` でシンボルが解決できれば `<symbol+offset>` を付与する |
| `c` | 文字（エスケープ表示付き） |
| `f` | 浮動小数点数として値のビット列を再解釈して表示（4バイトなら float、それ以外は double） |
| `s` | C 文字列（ポインタとして参照先を読む） |
| `z` | 16進数、型の全幅までゼロ埋め |

`i` も内部的には `d` と同じ扱いだが、GDB の `print` フォーマット文字には存在しない（GDB では `x` コマンド専用）ため `help print` には掲載していない。

#### leaks コマンド (cmd_leaks)

```
1. malloc_stack_logging が false → 警告を出力（スタックトレースなしで続行）
2. snprintf(cmd, "leaks %d 2>&1", pid)
3. popen(cmd, "r") で leaks 出力をそのまま stdout に転送
4. leaks が見つからない場合（"leaks not found" 出力）はエラーメッセージ
```

#### 停止時の PID/TID 表示

ブレークポイントヒット・ステップ完了など、プロセスが停止するたびに以下を表示する：

```
[PID: 12345  TID: 67890]
```

- `get_primary_thread_id(pid)` : Mach `THREAD_IDENTIFIER_INFO` フレーバーで `thread_id`（起動ごとにユニークな64bit値）を取得
- `print_stop_header(dbg)` : `dbg->current_tid` が `CDBG_TID_PRIMARY` なら `get_primary_thread_id` で先頭スレッドの tid を、そうでなければ `dbg->current_tid` の値をそのまま TID として `printf("[PID: %d  TID: %llu]\n", ...)` で出力する
- `report_stop` は PID/TID を表示する前に `switch_current_tid_to_breakpoint_hit()` を呼び、全スレッドの PC をブレークポイントアドレス群と照合して実際にトラップしたスレッドへ `current_tid` を切り替える。これにより表示される TID は「最後に選択されたスレッド」ではなく「実際に止まったスレッド」を指す
- 呼び出し箇所: `report_stop`, `cdbg_step_next_line`, `cdbg_next_source_line`, 初回エントリ停止（`cdbg_run` 内）

その後、ソースコードまたは逆アセンブルを `print_stop_location` で表示する（ソース情報がある場合はソース、ない場合は `dis`）。

#### set コマンド (cmd_set)

```
"var = expr" 形式をパース (split_assignment):
  1. 左辺が '$' で始まる → レジスタ代入モード
       a. cdbg_expr_eval で右辺を評価（is_float, fvalue を含む）
       b. cdbg_refresh_regs でレジスタ読み込み
       c. cdbg_regs_set_by_name(pid, current_tid, regs, reg_name, value, is_float, fvalue) で書き込み
  2. それ以外 → 変数代入モード
       a. resolve_set_lhs: 左辺を cdbg_ast_parse → cdbg_ast_resolve_lvalue で
          書き込みアドレス・サイズ・符号を解決（1.9 章の AST 評価器と共通）
       b. cdbg_expr_eval で右辺を評価
       c. 型サイズに応じて cdbg_mem_write
```

#### help コマンド (cmd_help)

```
cdbg_help_entry_t {
    const char *category;  // "General" / "Execution" / "Inspection" / "Breakpoints" / "Watchpoints" / "Settings"
    const char *names;     // "break, b"
    const char *usage;     // "break <addr|name|file:line|line>"
    const char *summary;   // 1行の概要
    const char *detail;    // NULL または複数行の詳細テキスト
}
```

| 関数 | 役割 |
|---|---|
| `print_help_entry` | `help` 一覧用：`  %-22s  %s\n` で names + summary を1行表示 |
| `print_help_entry_detail` | `help <cmd>` 用：usage + summary + detail（2スペースインデント）を表示 |
| `print_help_all` | カテゴリ見出し + 全コマンド1行一覧 + 式サンプル集 |
| `help_name_matches` | `names` フィールドのカンマ区切りトークンまたは `usage` 先頭との前方一致で検索 |

全コマンドに `detail` テキストを持つ。`help <cmd>` で書式例・サブコマンド・注意事項を確認できる。

#### kill コマンド

```
1. pid <= 0 or state == IDLE → "No process is running." を stderr に出力して return
2. killed_pid = dbg->pid を保存
3. stop_debuggee(dbg) : ptrace(PT_KILL) → cdbg_process_wait → pid=0, state=IDLE
4. printf("Process %d killed.\n", killed_pid)
5. REPL を継続（debugger は終了しない）
```

`quit` との違い: `kill` はデバッギを終了するが REPL に戻る。`quit` はデバッギを終了したうえでデバッガ自体も終了する。

#### stop_debuggee（quit / kill 時に呼ばれる）

```
1. pid <= 0 or state == IDLE → return 0
2. ptrace(PT_KILL, pid) : SIGKILL 相当でプロセスを終了
3. cdbg_process_wait() : zombie 回収
4. pid = 0; state = IDLE; breakpoints / watchpoints すべて disabled
```

`run` によるプロセス再起動時は `cdbg_run` 内で `breakpoint_count` / `watchpoint_count` を 0 にリセットする（ハードウェアウォッチポイントはプロセスごとのスレッド状態のため、旧プロセスの登録は引き継がれない）。

---

## 2. エラー処理方針

- すべての関数は `0` を成功、`-1` をエラーとして返す（`bool` 返しを除く）
- ptrace・Mach API のエラーは `perror` または `fprintf(stderr, ...)` で報告
- REPL コマンドのエラーは stderr に出力し、REPL を継続する
- `cdbg_continue` / `cdbg_wait` がエラーを返した場合は REPL を終了する（`return -1`）
