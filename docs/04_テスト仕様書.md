# テスト仕様書

## 1. テスト概要

### 1.1 テスト対象

`cdbg` の全コマンドおよびコア機能。テストは主に `build/target`（`examples/target.c` のビルド成果物）を debuggee として使用する。TC-12（スレッド）のマルチスレッドケースのみ `build/target_threads`（`examples/target_threads.c`）を使用する。

### 1.2 テスト環境

| 項目 | 内容 |
|---|---|
| OS | macOS 13 以降 |
| アーキテクチャ | ARM64 / x86_64 |
| ビルド | `make examples` |
| 実行 | `build/cdbg build/target` |

### 1.3 テスト種別

| 種別 | 内容 |
|---|---|
| 正常系 | 正しい入力に対して期待通りの出力が得られること |
| 異常系 | 不正な入力や未対応操作に対してエラーが適切に報告されること |

#### TC-02-09: マルチスレッドプログラムでの next/step/si 中の他スレッド停止

| 項目 | 内容 |
|---|---|
| 手順 | `build/cdbg build/target_threads` → `break main` → `run` → `next` を数回実行し、`pthread_create` の行を通過させる（ワーカースレッド生成後、`worker_counter` が毎秒 1 ずつ増える）→ 各 `next` の直後に `p worker_counter` |
| 期待結果 | `next` を何回実行し、実時間で何秒経過しても、`next`/`step`/`si` の実行中は `worker_counter` が変化しない（他スレッドは `thread_suspend()` で一時停止されている）。`continue` に戻れば通常通り増加する |
| 既知の制約（修正済み・回帰確認用） | 2026-07-24 以前は `PT_STEP` がカレントスレッドしか止めず、特に `pthread_create` のような間接呼び出しへの `next` が逐次シングルステップにフォールバックして実時間で数秒かかる間、ワーカースレッドが自由に動き続け `worker_counter` が背後で進んでいた |

#### TC-02-09b: next 実行中に生成されたスレッドが自分のブレークポイントに到達するレース（回帰確認）

| 項目 | 内容 |
|---|---|
| 手順 | `build/cdbg build/target_threads` → `break worker` → `break main` → `run` → `c`（main で停止）→ `n`（`pthread_create` の行をまたぐ）を 10 回程度繰り返す |
| 期待結果 | 毎回 `n` が正常に完了し、プロンプトに戻る（ハングしない） |
| 既知の制約（修正済み・回帰確認用） | TC-02-09 の対策（ループ開始前に他スレッドを一括で一時停止）だけでは、ステップの**途中**（`pthread_create` 実行中）に新しく生成されるワーカースレッドまでは一時停止できていなかった。ワーカースレッドが `next` の完了より先に自分自身のブレークポイントへ到達すると、メインスレッドの `PT_STEP` 完了を待つ `waitpid()` が永久にブロックする不具合があった（体感で 10 回に 1 回程度の頻度で再現）。ステップループの各反復で新規スレッドを検出し次第即座に一時停止するよう修正済み（`step_thread_guard_catch_up`） |

#### TC-02-09c: 非プライマリスレッドが current のときに next/step/si を実行すると拒否される（回帰確認）

| 項目 | 内容 |
|---|---|
| 手順 | `build/cdbg build/target_threads` → `break worker` → `run` → `c`（ワーカースレッドのブレークポイントにヒットし `current_tid` がワーカーに切り替わる）→ `si`（または `n`/`step`）を複数回連続実行 → `thread 0` → `si` |
| 期待結果 | `current_tid` が非プライマリの間は毎回 "Cannot single-step: the current thread is not the primary thread. ... Run 'thread 0' ..." というエラーが表示されるだけで、実際のステップは行われず、ハングしない（連続実行しても同様）。`thread 0` でプライマリに戻ったあとの `si` は通常通り実行される |
| 既知の制約（過去に試みて撤回した対策） | 2026-07-24 の最初の対策は、一時停止対象からプライマリスレッドを除外した上で「非プライマリのときは注意を表示するだけで実行は許可する」方式だったが、`n` を連続実行すると数回に 1 回の頻度で `waitpid()` がハングする問題が残っていることが判明した（`PT_STEP` が実際にどのスレッドをステップ対象にするかがカーネル側の状態に依存し非決定的なため）。最終的に、非プライマリスレッドが current のときは `step`/`si`/`next` の実行自体を拒否する方式に変更し、ハングを完全に防止した |
